DATASTAGE - SUPPLIERS EN PostSCSTH

APLICAR
1. Extrae el ZIP completo y ejecuta APLICAR.bat. Selecciona la carpeta de tu proyecto DataStage si se solicita.
2. El aplicador verifica la rama y el parche antes de modificar archivos. Crea un respaldo junto al proyecto. Una version incompatible se detiene sin aplicar el parche.
3. Reinicia backend, worker y frontend con tus tres comandos habituales.

LECTURA DE EXCEL
El backend usa openpyxl para .xlsx (ya figuraba en requirements.lock) y xlrd 2.0.1 para .xls (nuevo).
Actualiza esas dependencias con el mecanismo autorizado de tu entorno. Si tu entorno permite pip, desde la raiz del proyecto:
  .venv\Scripts\python.exe -m pip install xlrd==2.0.1 openpyxl==3.1.5
El aplicador no instala paquetes. Si xlrd no esta disponible, puedes seleccionar las dos listas guardadas como .xlsx desde Excel.

USO
En Suppliers veras Extranjeros y Nacionales. Como administrador, abre Importar listas iniciales y selecciona ambos Excel originales una sola vez. Tambien funciona si ya habias procesado meses.
Importar y reconocer proveedores incorpora los faltantes y reevalua las coincidencias automaticamente. Si las listas ya estaban inicializadas, pulsa Actualizar coincidencias para reevaluar el historial existente.
Las cargas siguientes preparan ambos archivos automaticamente. Los nuevos proveedores se resaltan en amarillo. Las decisiones se conservan y los conflictos se agrupan por identidad, sin repetirlos por domicilio.
Los archivos de un reporte existente se descargan desde la misma instantanea; las descargas no generan reportes adicionales. Los reportes anteriores permanecen inmutables. Una importacion posterior se refleja en las siguientes listas o en un reporte adicional.
Las diferencias de identificacion fiscal, las coincidencias ambiguas y los proveedores nuevos sin pais suficiente siguen como incidencias. No se ocultan ni se exportan como datos confirmados.

ALCANCE
Base revisada: ae7a051 de PostSCSTH. Incluye codigo, pruebas, contrato API y documentacion; no incluye tus Excel privados, base de datos, documentos, node_modules ni entornos virtuales.
La actualizacion conserva la rama y no abre ni modifica la base de datos durante la aplicacion.
Despues de reiniciar, la reevaluacion del historial se realiza desde la propia funcion Suppliers.
